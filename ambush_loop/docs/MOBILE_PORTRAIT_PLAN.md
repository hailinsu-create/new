2026-09-07。只读核对基线 `8608cdd2f1ecef4c673b3e57b0f89cc0a330b066`，分支 `codex/mobile-first-pass`。本文件是待实施契约，不是制作完成或测试通过报告。父代理负责基线与 CI 检查，本规划不重复。父代理报告 CI 两个接口为空且暂未发现 workflow，不能称 CI 通过。

## 1. 首轮范围

交付一个默认安卓竖屏、720×1280 逻辑视口、无键盘即可完成院子→仓道→泵站的可玩版本。重做三关纵向战场与触控操作，保留当前规则系统；占位美术允许，但必须有清晰信息层级、选中/合法/非法反馈与可读中文。首轮不做完整时间轴、迷雾、商业美术、成长、联网。安卓导出与真机是独立验证层，缺少设备或 SDK 时明确未验证。

铁律：警报后部署、朝向、开火条件、装备、绊索、门全部不可修改；一个敌人逃逸同 tick 失败；失败保留幽灵及上轮计划，重试恢复战斗资源。

## 2. 竖屏布局与关卡策略

采用上下布局，禁止横图等比缩到手机中间或旋转现有关卡充当完成。参考720×1280安全区域：顶栏约112高，战场约720高，底部指令区约400高，余量为边距。以容器实际可用空间计算，不硬编码屏幕绝对坐标。

- 顶栏：关卡/轮回、阶段、简短目标与记忆数量，详细帮助折叠。
- 中部：完整可见的纵向战场，入口在上、逃逸口在下；主路贯穿中轴，侧翼经左右边道汇入出口。地图约20列×24行、TILE仍32，可从640×768世界范围起步。最终尺寸由Luna结合触控可读性调整，必须保持纵向而非宽图裁切。
- 底部：三张等宽队员卡；选中对象的部署状态、弹药与模式；朝向左/右15°及“点地图瞄准”；情境工具行；独立醒目的警报按钮。观看时替换为暂停/1×/2×和简短事件；详细日志在可关闭面板内滚动。
- 结算采用居中或底部面板：原因、最近关键事件、保留计划重试/下一关、查看战场。面板不能让触摸穿透。清空记忆与普通重试分开，清空操作有明确确认。
- 所有必要按钮触摸区域至少96×96逻辑单位（720缩至360宽时为48像素），间隙至少12；正文建议28–32逻辑单位。地图掩体命中区按屏幕大小扩展，不能因缩放变成微小目标；近邻命中用最近距离+稳定ID决定，标明最终目标。
- 适配360×640、390×844、412×915窗口：整张战场、逃逸口和主操作始终可见；较长屏增加留白/战场空间，不拉伸几何。读取可用安全区域并保留降级边距。首轮不依赖缩放/平移手势完成部署。

三关必须重新编排坐标、遮挡、保护方向、伏击区、出生/出口和门：院子教主侧路覆盖；仓道教入伏时机与弹包；泵站教锁门改方向。每关保留6个可部署位、3人及作者预设路线。不得仅压缩X坐标使墙体或射程意义失真。保留稳定level_id/slot_id；若旧计划坐标不适用，版本化或安全迁移，不能无声加载墙内方案。

## 3. 与 main.gd 的适配边界

基线风险：`grid.gd` 固定40×22；`main.tscn` 固定横屏栏；`_resolve_optional_hud()`动态追加800宽按钮栏与右上日志；`_unhandled_input()`只处理键鼠，命中依赖`get_global_mouse_position()`。模拟、LOS、拾取、日志广泛使用`global_position`。

Luna实施边界：

1. 保留`_sim_tick`、终局顺序、战斗数值和BattleLog语义。只为新关卡调整必要内容，不借机全量重写模拟。
2. 提取独立触控HUD脚本/场景负责布局与信号；复用`_select_op`、`_deploy_selected_to`、`_on_mode_pressed`、`_on_pack_pressed`、`_on_door_pressed`、警报/暂停/继续入口。替换动态横栏创建及路径绑定，不能保留隐藏重复按钮和双重信号。
3. 统一准备命令入口检查phase与locked；HUD禁用只是表现，合成输入/旧快捷键也不能绕过锁定。保留桌面快捷键作为辅助。
4. 建立唯一屏幕→战场坐标入口。优先用Camera2D/canvas变换呈现原单位世界，保持World及实体父节点单位变换；不要缩放World后继续把global_position直接当网格坐标。若改用SubViewport，输入转换只做一次并测试各尺寸；避免同时混用两套坐标。
5. 网格尺寸、地图绘制、路线、伏击矩形、门、掩体和保护角度同步修改；所有路线线段需可通行，开/锁门均有有效备用通路。
6. 触控以点选为主：卡片选人→点掩体部署→左右按钮或进入瞄准模式后点战场确定朝向。瞄准触摸不得重新部署；绊索模式提供放置、撤除/取消入口与数量反馈。记录单个活动pointer，忽略额外手指；释放/取消清理状态。UI消费事件，处理触控与模拟鼠标重复触发。
7. `_update_hud`输出状态交给HUD展示，移除以快捷键为唯一说明的文案。准备/观看/结算阶段控件集合明确。

## 4. Luna执行顺序及交付物

- T0 存档安全：当前smoke的`_wipe_save()`直接删除`user://ambush_loop.cfg`，不是隔离。先做可注入测试存储路径或独立测试user目录；在加载场景前设置。测试路径必须唯一且与生产路径不同，缺失隔离配置即失败退出；清理只作用于测试目录。禁止删除玩家存档或以备份恢复代替隔离。
- T1 纵向地图：三关真实重新布局，统一网格/碰撞/门数据，提供可运行且确定性的各关参考胜利方案。不得为迁就旧测试伪造WON或跳关。
- T2 竖屏HUD与触控：默认纵向视口及方向配置，完成全部触控动作、阶段锁定、日志/结算与重试。
- T3 回归与证据：更新地图变化后的smoke；增加有实际输入分发的触控流程验证与锁定/存档隔离回归；提供各关准备、观看、失败、成功截图及运行日志、命令、版本、未验证项。
- T4 Astra只读审查→Luna修正→针对问题回归；无阻塞缺陷后才宣布本轮验收完成。不提交/推送，交由父代理协调。

| 必须通过 | 可核实证据 |
|---|---|
| 全触控闭环 | 经真实UI输入完成选3人、部署、两种调射界、模式、弹包、绊索撤放、第三关门、警报、暂停/变速、失败重试和三关胜利；直接调用内部方法不能证明触控通过 |
| 纵向关卡可解 | 三关新几何校验；每关参考方案实际WON；泵站开门与锁门均实际运行并获胜；至少一次实际escape失败且恢复幽灵与计划 |
| 锁定及时间不回归 | 观看中触摸地图/卡片/旧快捷键无法修改计划；暂停tick、伤害与绊索不推进；同方案1×/2×按模拟tick对齐关键事件与结局 |

| 阅读与布局 | 三关地图完整、无横向HUD溢出，中文字体实际渲染无方框，按钮可见且达到触摸尺寸，日志与结果长文本可读，无被安全区遮挡入口 |
| 存档安全与继续 | 隔离环境放置“生产路径哨兵”验证测试不改动其字节；正常保存重载落在目标关卡；测试异常退出也不能碰玩家目录；新旧计划兼容策略明确 |
