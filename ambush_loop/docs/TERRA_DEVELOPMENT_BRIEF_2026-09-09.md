## 二、产品与美术方向

建议方向：原创“雨后工业港区的微缩战术场景”，正俯视、风格化 2D、简化体块与克制纹理。院子以水泥、砖墙、沙袋和装卸设施建立空间层次；角色以头盔、肩部、武器方向和统一阴影清楚表达朝向。暂不使用复杂 3D、整屏重光照或高密度写实细节。

美术必须强化决策信息：

- 环境采用低饱和灰蓝/灰绿，友军偏青绿、敌军偏暖橙；危险出口用红色标志，记忆路径用紫青虚线。颜色之外必须同时有轮廓、编号或图标，不靠红绿区分敌我。
- 可部署掩体有明确底座、可用高亮和保护方向；纯装饰物不得画成同样形态。角色与掩体的实际位置、命中区和遮挡必须一致。
- 当前选中队员的射界突出；其他队员降低不透明度。固定路线与幽灵线使用不同线型；观看时减少非必要辅助线，复盘时可重新查看。
- 720×1280 是布局参考。地图保持纵向完整可见，出口不能被底部按钮遮住。禁止为了大立绘挤压战场。
- 所有必要触控目标在最小支持尺寸下验证，包括菜单、设置、确认框、结算和关卡选择；96逻辑单位只是现有720宽设计基准，实际设备还需验证手指命中。

## 三、首批美术清单与资源规范

| 类别 | 一关样板必需内容 | 交付与验收 |
|---|---|---|
| 场景 | 一套地面/墙边/墙角、三种不同轮廓的掩体、门开关、入口出口、少量装饰 | 同一光照方向和比例；战术物与装饰物可分辨 |
| 角色 | 友军基础身体与三种身份标识、敌军基础身体、死亡姿态 | 先保证手机原尺寸下敌我/朝向可读；不提前制造不存在的职业技能暗示 |
| 道具 | 绊索两端与线、弹药拾取、备用弹包、门锁状态 | 准备/已部署/触发或耗尽各有明确状态 |
| UI | 队员卡、选中/禁用态、警报主按钮、模式/补给/幽灵图标、结算与评分图例 | 图标有文字补充；短文案替代键盘快捷键堆叠 |
| 特效 | 枪口、短弹道、人物命中、墙体命中、倒地、拾取、逃逸定位、回溯 | 不遮住射界与漏网敌人；暂停与倍速行为明确 |
| 声音 | 部署/取消、警报、敌我枪声、命中、空弹、拾取、逃逸、成功、回溯、轻环境底音 | 同时开火不爆音；音乐/音效总线可独立控制 |

建议目录：`art/environment`、`art/units`、`art/ui`、`art/fx`、`audio/sfx`、`audio/ambience`、`scenes/visuals`。人物可用透明 PNG 图集和分层 Sprite2D；图标可用原创 SVG。角色身体不随瞄准随意镜像导致编号反转，身份标签独立绘制。

首关先采用统一部件与调色复用，不要求一开始做大量八向逐帧图。先以身体/武器分层实现转向与后坐力，再按实机观感决定是否补方向图集和跑动帧。效果必须在实际战场缩放下验收，不只看原始大图。

若使用生成式图片，先做统一风格样张，再处理透明背景、切图、锚点、尺寸和图集；整幅概念图不能算已经接入游戏。角色UI文字必须由引擎排版，不烘焙进生成图。保存资源来源、作者/工具、许可和加工记录；不得引入既有 IP 的人物或标志。

## 四、动画与模拟契约

| 事件 | 建议表现时长 | 规则约束 |
|---|---|---|
| 选择/部署 | 80–160ms 高亮/落位 | 状态立即提交，动画不延后部署命令 |
| 转向 | 80–140ms 武器转动 | 真实射界立即更新，或同步显示最终射界，不能用动画角度结算 |
| 行进 | 步态循环+小幅身体摆动 | 路线和速度由 SimClock 决定，画面插值不能改坐标判定 |
| 开火 | 40–80ms枪口，80–140ms后坐 | 每个实际开火事件触发一次，不按画面帧率生成伤害 |
| 命中/掩体 | 80–160ms短反馈 | 命中与掩体减伤视觉有区别；不通过动画回调扣血 |
| 死亡 | 180–300ms倒地 | 单位在模拟死亡的tick立即失去攻击/拾取资格 |
| 拾取/断弹 | 120–220ms图标反馈 | 展示真实拾取归属；断弹只在状态变化时提示，避免刷音效 |
| 警报 | 250–450ms阶段转换 | 点击时立即锁方案；建议转换完成后才启动模拟，不隐藏开战前几tick |
| 逃逸 | 150–250ms出口/单位定位 | 同tick失败，不能因终局动画继续伤害或产生第二次结算 |
| 回溯 | 400–700ms记忆轨迹/淡变 | 可跳过；切换前清理旧特效和引用，不能展示虚构的反向模拟事实 |

新增表现层如 `BattlePresentation`/`UnitVisual`：消费有序战斗事件，用回合ID+tick+事件序号去重。显示日志或重开面板不能重播枪声。不要把伤害、掉落、逃逸绑定 AnimationPlayer/Tween 完成信号。

观看暂停必须冻结战斗特效，菜单按钮动画可继续；2×时战斗动画按模拟时间推进，音效允许限流但不能变成刺耳双倍音高。新局、切关、回菜单时清理过期效果。减弱动态模式关闭大幅位移/震屏和强闪烁，用淡入淡出替代。

## 五、执行批次（Terra按顺序完成）

### T0：修规则与交付缺口

- 保留当前工作树，记录本批起点与新增文件；移除 export_presets.cfg 忽略或生成可跟踪的无密钥配置。核实引擎实际支持的导出键，不能仅解除忽略便认定 AAB 可导出。
- 评分改为最终胜利方案的存活表现：零逃逸通关1星、至少2名队员存活2星、3名存活3星；轮回次数独立记录，不扣星。最高评分只增不减。
- 不采纳前次未实施的“剩余9发才三星”临时提议：拾取会影响余弹，且未经平衡验证。后续挑战目标另设，不影响基础星级。

- 补测前端实际按钮尺寸。建立本批隔离回归入口，先确保基线能运行，再进入美术接入。

### T1：院子一关视觉与动作完整接入

- 先输出院子准备态风格样张和真实场景截图对照；确认角色/掩体尺度可读后，再实现上表核心资源。样张不等于游戏截图。
- 接入环境、角色、UI主题和战斗表现层；优先覆盖选择→部署→警报→枪战→失败→改计划→胜利整个闭环。
- 失败摘要提供事实和建议两部分：终止事件是谁/何时/在哪里，相关断弹或阵亡事件；没有日志证据不能断言“因为LOS遮挡”。建议措辞为“下次可尝试”，不伪装成已证明的因果。
- 一键查看漏网路线，回到准备保留原计划；幽灵可开关且不影响模拟。最先只做好院子，不同时重画全部三关。
- 输出准备、观看、失败定位、重试、胜利截图及一段实际运行录像；视觉验收未做则明确标注。

### T2：选关与三关统一品质

- 添加关卡选择、解锁与最佳成绩；解锁最高关单独保存，重玩旧关不得丢失后续解锁。版本迁移保持旧进度，不将某关记忆误加载到另一关。
- 仓道、泵站复用美术/动画系统，以地标与掩体布局建立区别；门与路线变化必须在准备阶段可预览并和模拟一致。
- 至少5名首次玩家观察测试；内部建议目标为4/5能在3分钟内启动第一场战斗，4/5能说明一次失败后打算改什么。当前没有这些测试结果。

### T3：扩战役与Android质量

- Android工具链探测与开发APK应从T0同步推进，工具缺失不阻塞软件内容迭代，但未安装设备不能记为移动端通过。
- 样板成立后先扩到6关复核战术差异，再向12关/3章目标推进；不按静态通关脚本估算45–90分钟体验时长。
- 实机检查最复杂场景性能、发热、声音并发、字体/安全区、返回/后台/进程终止/升级存档。主流60FPS、目标低端30FPS是待实测目标。
- 签名AAB、正式图标/商店素材、隐私政策及Play测试轨道在内容验收后封板；以当期官方要求核对，不以预设中的SDK数字作为发行合规证明。

1. 自动化：评分不随轮回改变；同一方案在动画开/关、1×/2×、暂停恢复后得到相同有序战斗日志与终局；逃逸同tick锁死；重试恢复计划；生产存档字节不变。只对相关改动运行必要回归。
