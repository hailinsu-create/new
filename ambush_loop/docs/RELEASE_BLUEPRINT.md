# Ambush Loop 首发可留存手游发行蓝图

本蓝图把验收目标从“技术上可以导出”提升为“玩家首次安装后能理解、完成、失败后愿意重试，并能继续推进的手机游戏首发版本”。首发保持离线单机，不加入联网、广告或付费系统。

## 玩家首发门槛

- 首次启动进入主菜单：标题、开始游戏、继续、设置、关于/隐私入口均可触控；没有键盘也能开始。
- 开始游戏进入一次性新手引导。引导按真实输入推进：选人、部署、调射界、使用工具、拉响警报、观看锁死的战斗、阅读失败/情报、重试。当前步骤有文字说明、目标高亮和成功反馈；README 只作为补充。
- 三关有清晰节奏：院子教学交叉封锁，仓道引入弹药与入伏时机，泵站以锁门改写侧翼路线形成高潮。每关显示目标、关键规则和战后评价。
- 每次失败保留逃逸路线幽灵、上轮计划和轮回次数；每次胜利显示 1–3 星、评价、关键事件和下一关/再试入口。星级由轮回数、存活队员与失败次数等真实结果计算，不能伪造通过。
- 结算面板可查看战场、继续/下一关、重试；观看阶段可暂停和 1×/2× 观看；触摸和旧快捷键都不能修改已锁死计划。
- 设置至少提供音量、震动/触控反馈开关，并明确中文首发；关于页说明离线存档、无联网/广告/分析，并提供隐私政策草案入口和待填支持邮箱字段。
- Android 返回键优先关闭事件日志、帮助/关于、设置或结算覆盖层；后台/失焦时观看阶段自动暂停，回前台保持暂停等待玩家继续。
- 360×640、390×844、412×915 与 720×1280 下，地图、逃逸口、核心按钮和结算文本均在安全区内，按钮和正文可读。
- 核心规则保持不变：警报后方案锁死、零逃逸才胜利、失败保留情报、战斗不微操。

## 存档与数据边界

- 存档 schema 显式版本化，保存 `level_id`、`level_index`、`loop`、幽灵情报、上轮计划、各关最高星级、教学状态和本地设置。
- 只在菜单、准备阶段或结算阶段写入安全状态；不保存进行中的敌人、弹道、冷却或战斗 tick。
- 写入先落临时文件，再替换目标文件；损坏或未知版本回退到安全新档并记录原因。旧的简单进度字段可迁移，缺失的计划/情报按空值处理。
- 自动化测试使用唯一 `user://test/...` 路径，并以生产 `user://ambush_loop.cfg` 字节哨兵证明隔离。

## 证据分层

| 层级 | 必须记录 |
| --- | --- |
| 静态 | 工程身份、版本、Compatibility renderer、竖屏、权限审计、存档 schema、发行清单 |
| 桌面 | 主菜单、引导/触控、三关节奏、失败情报、星级结算、设置、返回键/失焦逻辑、截图 |
| 合成输入 | `InputEventScreenTouch` 驱动的菜单、教学和战斗关键路径 |
| Android 导出 | 实际 Godot Android 模板、SDK/build-tools、JDK、AAB/APK、aapt/apksigner/16 KB 检查 |
| 模拟器/真机 | 安装、启动、返回键、后台恢复、字体、触控、设备截图 |
| Play Console | 签名上传、Data safety、内容分级、商店资料和测试轨道；没有实际操作就保持未完成 |

本文件是目标与验收契约。完成哪些层级必须以 `outputs/release_candidate_packet.md` 中实际命令、版本和 exit code 为准。
