## 0. 先给结论（再往下看路线）

| 轨 | 定位 | 玩家在手机上实际做什么 |
|---|---|---|
| **手机默认 · 简配夜袭** | 触屏主路径。一次深度操作一人；世界动词靠情境热区；警报是观战。 | 点肖像选人 → 点地走 / 点匣开 / 点岗哨割或引 → 点掩体趴下 → 拉警报 → 暂停/倍速。 |
| **桌面完整 · 敢死队工具** | 键鼠主路径。v0.5 全套保留。 | 1/2/3、点地、C/Q/W/Z、I、G、H、T、Shift 慢走、双击跑、滚轮、F1/F2。 |

**若只做一件事：把 SETUP 那一排 14～16 个底栏键拆掉，改成「靠近目标才弹出 1～2 个大热区」，并把底栏三张肖像从地图中央挪回拇指带。**

理由不玄：`C2ContextCursor` 已经能分辨 开匣 / 搜尸 / 趴下 / 割喉 / 选中，只是现在跟着鼠标走，手指会挡住，也没有热区。底栏是把 `COMMANDOS_RAID.md` 输入表逐行译成按钮。肖像条的锚点写在桌面 Root 上，触控又把 Root 底边抬了 150px，结果三张脸印在院子正中（见 §1.3）。这一刀同时修溢出、误触、重复身份、拖尸没键、地图被挡。

不要先做：两阶段意图条、跟班 AI、竖屏、把 RAID 改成 Hitman GO 棋盘。那些是后手。

## 1. 现状：为什么这块屏塞不下

### 1.1 现在屏幕上同时活着几套 UI

v0.5 在「每条键盘命令一个肥按钮」的触控底栏上，又加了一层敢死队 chrome。触控开时（Android / `GameSettings.force_touch_hud`）它们**一起亮**：

| 层 | 文件 | 尺寸 / 锚点 | SCOUT | ALERT |
|---|---|---|---|---|
| 左轨三张兵种卡 | `ui/op_card.gd`，触控时 220×142×3 | 左缘，约 442px 高 | 开 | 开 |
| 底栏三肖像 | `c2/portrait_strip.gd` 104×108×3 | `offset_top -272`～`-158`（相对 HUD/Root） | 开 | 开 |
| 技能条 C/Q/W/Z | `c2/skill_bar.gd` 5×(54×62) | 右下 `offset_top -228` | 开 | 关 |
| 小地图 | `c2/minimap.gd` 184×104 | 右上 | 开 | 开 |
| 情境光标 | `c2/context_cursor.gd` | 跟随鼠标 +14,+10 | 开（跟鼠标） | 关 |
| 触控底栏 SETUP | `touch_hud.gd` `_row_setup` | 底 156px，键 78×56 | **14～16 键** | 关 |
| 触控底栏 WATCH | 同上 `_row_watch` | 同上 | 关 | **10 控件** |
| 顶栏路线芯片 / 时间轴 / 阶段 | `main.gd` HUD | 顶 ~110px | 开 | 开 |
| 6 格背包面板 | `ui/backpack_panel.gd` 右缘 420px | 模态 | I / 背包 | 可开 |

2026-09-13 窗口 dump（1280×720，`force_touch_hud`）：

```
DUMP_CHROME tag=scout  setup_btns=14  portraits=true  skillbar=true  minimap=true  left_cards=true
DUMP_CHROME tag=alert  watch_btns=10  portraits=true  skillbar=false minimap=true  left_cards=true
```

院子 SCOUT 底栏实拍 14 键（弹包/门锁按关卡藏）：

**开火 · 绊索 · 雷点 · 背包 · 诱饵 · 匍匐 · 割喉 · 口哨 · 捆绑 · 递装 · ↺ · ↻ · 收回 · 需枪**

仓道/泵站有弹包和门锁时是 **16 键**。`touch_hud.gd` 里 SETUP 全表就是这 16 个。

### 1.2 像素账（虚拟 1280×720，`stretch/mode=canvas_items` + `aspect=keep`）

SETUP 行：

```
16 × 78px + 15 × 6px 间距 + 左右 margin 8+8
= 1248 + 90 + 16 = 1354px  >  1280px
```

院子 14 键 ≈ 1186px，在桌面强制触控里勉强排下，左右安全区各 40px 的真机就会裁掉最右的 **需枪**——而这是提交键。

纵向：

| 带 | 约占用 |
|---|---|
| 顶栏 + 路线芯片 | 110px |
| 触控底盘 | 156px（`BarPlate.offset_top = -156`） |
| 肖像+技能（设计意图） | 再 110px，本应叠在底盘上 |
| **地图剩** | 设计意图约 340px / 720 ≈ **47%** |

横屏手机（物理 2400×1080 映到 1280×720）上，78px 键约 9–10mm，单键够大，**键太多**才是问题。

### 1.3 布局事故：肖像印在院子中央

`main.gd` `_apply_phone_chrome` 在触控时把 `HUD/Root.offset_bottom` 设成 `-150`，给底栏让位。  
`c2_director.gd` 的肖像/技能条锚在这个 Root 上，数值却按**未压缩的 720 底边**写：

```
portraits: offset_top -272, offset_bottom -158
skill_bar: offset_top -228, offset_bottom -160
```

Root 底边被抬到 y≈570 之后：

- 肖像顶 ≈ 570−272 = **298**（屏幕 41% 处）
- 肖像底 ≈ 570−158 = **412**

所以 [`01_scout_touch_crowded.png`](eval_touch_ux/01_scout_touch_crowded.png) 里三张脸盖住中庭匣和 MG42，[`02_alert_touch_watch.png`](eval_touch_ux/02_alert_touch_watch.png) 里警报中三张脸还盖在三人掩体上。这不是「敢死队 chrome 太多」那么抽象，是**触控 Root 压缩和 C2 锚点没对过表**。

### 1.4 1:1 键位映射已经自相矛盾

| 键盘 | 触控底栏 | 技能条 | 实际 |
|---|---|---|---|
| C 匍匐 | 有「匍匐」 | 有 C | **三处**（左卡还盖「匍」戳） |
| Q 割喉/埋雷/望远镜 | 有「割喉」，没有埋雷/望远镜 | 有 Q | 铁砧埋雷、夜枭望远镜只活在技能条上，而技能条在触控时压着地图 |
| W 口哨/诱饵 | 「口哨」+「诱饵」两个键 | 有 W | 角色技能和道具按钮重复 |
| Z 包扎/捆绑 | 只有「捆绑」 | 有 Z×2 | 包扎在触控底栏缺席 |
| G 雷点 | 有 | — | 合理，常驻候选 |
| I 背包 | 有 | — | 合理 |
| H 拖尸 | **无键** | — | `apply_touch_command("haul")` 写了，`_add` 没做。触屏拖不了尸 |
| T 递装 | 有 | — | 离背包流程远，误触 |
| Tab 绊索 | 有 | — | 工具模式，占一格常驻 |
| A/D 射界 | ↺ ↻ | — | 微调 15°，拇指难精 |
| F 开火条件 | 有「开火」 | — | 搜刮期不该占主栏 |
| Space 警报 | 「需枪」 | — | 必须常驻，应是最大键 |
| 双击跑 / Shift 慢走 | 无 | — | 触屏只能点地走 |

情境光标（`context_cursor.gd`）探测半径 **22–26px**，跟鼠标。触屏最后一次点击会留下一个被手指挡住的标签，不是可点热区。

**诊断一句：** v0.4 的触控底栏已经在翻译 RAID 布置键；v0.5 又把 Commandos 2 的肖像+技能+光标加进来，两套都没删。小屏痛点是产品层重复，不是格子太小。

## 2. 路线 1 — 减负 / 分层（桌面完整 · 手机简配）

**主张：** 同一套模拟，两套动词表。手机默认不删岗哨黄锥、不删 6 格背包、不删自动手雷；只把「必须用第二只手或精确瞄准」的动词藏起来或自动掉。

### 2.1 动词表（对着现在的键）

| 动词 | 桌面完整 | 手机默认 | 为什么这样切 |
|---|---|---|---|
| 点选 1/2/3 | 键 + 左卡 + 肖像 | **只留底栏肖像** | 左卡与肖像重复。触控左卡 220 宽，吃掉西侧出生点 |
| 点地走 | 单击走、双击跑、Shift 慢走 | 单击走；**长按目的地 = 跑** | 双击在触屏是误触源 |
| C 匍匐 | 键 + 技能条 | 肖像旁一颗**粘滞**「匍」 | 站/蹲是状态，不是一次性技能 |
| Q 割喉 | 键 + 技能条 | **情境热区**（背后才出） | 已经有正面惊动规则，不要再按 Q |
| Q 埋雷（铁砧） | 键 | 技能轮 或 「布置」意图下点地 | 空地技能，不是世界物 |
| Q 望远镜（夜枭） | 键 | 技能轮 | 空地技能 |
| W 口哨/诱饵 | 键 | 近岗哨热区「口哨」；诱饵进轮 | 口哨是对岗哨的，诱饵是对空地的 |
| Z 包扎/捆绑 | 键 | 近伤员/倒地岗哨才出热区 | 底栏常驻捆绑是空按 |
| G 雷点 | 键 + 底栏 | 布置意图下点地，或一颗「雷」直到放下 | 不要 16 键里占一格 |
| I 背包 | 键 + 右缘 420px 面板 | **底栏一颗「包」→ 下方面板**（3×2，格 ≥ 140×88） | 现面板在右缘，挡技能条和小地图 |
| T 递装 | 键 | 只在背包面板里 | 底栏「递装」离人太远 |
| H 拖尸 | 键 | **近尸体热区**（补上缺失的触控） | 现在手机根本拖不了 |
| E 开匣 / 搜尸 | 走近 0.4s / 点匣 | **点匣/点尸 = 走过去并搜** | 触屏不要再要「站定」手感 |
| Tab 绊索 | 工具键 | 简配可藏；完整触控进「布置」 | 六夜里只有部分夜需要 |
| ↺ ↻ 射界 | 键 / 右拖 | 选中干员身上拖弧，**删掉两个旋转键** | 15° 步进不适合拇指 |
| F 见敌即打 / 入伏 | 键 | 进背包或肖像角标 | 搜刮期不是主操作 |
| 收回部署 | 底栏 | 进暂停菜单 | 危险键，不该和「需枪」并排 |
| Space 拉警报 | 大键 | **右下唯一大 CTA**（需枪 / 拉警报 / 下一波 / 撤离） | 提交键，永远可见 |
| 小地图 | 开 | **手机关**；平板开 | 点小地图选人与点肖像重复，还和阶段芯片抢右上 |
| 镜头 | 滚轮 / 中键 / F1 F2 | 跟选中人（`cam_follow` 已默认开）；双指缩放可后做 | 肖像双击拉镜头在触屏很难点准 |

### 2.2 简配还可以自动的（可选，第二刀）

仓库里已经有两个开关没被产品用起来：`GameSettings.hold_to_move`、`GameSettings.few_crates`。

| 自动 | 做法 | 利 | 弊 |
|---|---|---|---|
| 默认匍匐 | 手机 SCOUT 进关即蹲 | 少一颗键；岗哨黄锥更好用 | 院子教程「按 C」要改；打扫期搬运变慢 |
| 点岗哨 = 自动绕背后 | 点锥内岗哨，寻路到背刺格再割 | 真·少微操 | 路径穿过另一锥会暴；要显示 dest X 让玩家取消 |
| 点匣即搜 | 已有走近搜，补「点匣下指令」 | 符合直觉 | 无 |
| 少匣 | `few_crates` | 少开匣少背包 | 削弱搜刮组合，桌面不要开 |

**建议：** 第一刀只做「键藏起来」，不要做「AI 替你绕背」。绕背寻路是新失败模式。

### 2.3 利弊与优先级

- **利：** 玩法契约不动；桌面零损失；手机立刻少 10+ 个误触源。
- **弊：** 两套动词表要教（标题「操作说明」已按平台分过触控表，改那一页即可）；「简配」被理解成阉割 —— 文案写成「触屏用情境动作，键鼠用热键」，不要写「简易模式」。
- **优先级：P0（和路线 2 同一刀落地）。** 分层是原则，情境动作是手段。

## 3. 路线 2 — 情境动作（context actions）★ 推荐先做

**主张：** 常驻按钮 ≤ 4。世界里的动词跟在目标旁边，1–2 个 ≥ 120×48 的热区。

### 3.1 用现成分类，不要新规则

`c2/context_cursor.gd` 的 `Mode` 已经是产品表：

| Mode | 现 caption | 手机热区（选中干员走近后） | 第二热区 |
|---|---|---|---|
| `CRATE` | 开匣 | **开匣** | — |
| `CORPSE` | 搜尸 | **搜尸** | **拖尸**（补 H） |
| `COVER` | 趴下 | **上掩体** | — |
| `KNIFE` | 割喉 | 在背后：**割喉** | 在正面/侧面：**口哨** |
| `OP` | 选中 | 点另一人 = 选中 | 近距离：**递装**（少用，可只放背包） |
| `WALK` | （空） | 无热区，点地即走 | 长按 = 跑 |

探测半径从 22–26px 提到 **48–64px**（约一格半）。热区锚在**目标世界坐标的上方**，不跟鼠标、不跟最后一次点击。手指抬起后热区留 1.2s，避免「按下的瞬间标签还在指腹下」。

倒地岗哨（`sentry.is_down()`）出 **捆绑**；己方伤员出 **包扎**。这两条现在只在 Z 和技能条上。

雷点：不要常驻。进入「布置」或长按空地 → 一颗「雷点」芯片；再点取消。逻辑仍走 `_place_nade_mark()` / `G`。

### 3.2 常驻底栏（手机 SCOUT）只留这些

```
[ 灰狼 ] [ 铁砧 ] [ 夜枭 ]     [匍] [包]                    [ 需枪 ]
  选中放大                     粘滞  背包                   右下 CTA
```

- 开火 / 绊索 / 诱饵 / 割喉 / 口哨 / 捆绑 / 递装 / ↺ / ↻ / 收回：**全部离开常驻行**。
- 技能条（右下 5 键）：手机默认 **隐藏**，改由肖像长按出轮（路线 3）。
- 左轨三卡：手机默认 **隐藏**。HP/弹/枪印在肖像上（肖像已有 HP 条和枪戳）。

### 3.3 利弊与优先级

- **利：** 直接复用 Mode 枚举和 `apply_touch_command`；补上拖尸；割喉的「背后才能割」变成热区出不出现，而不是多按一次 Q；底栏宽度从 1354px 降到「3 肖像 + 2 小键 + 1 CTA」，任何安全区都排得下。
- **弊：** 空地技能（望远镜、诱饵丢点、铁砧埋雷）没有世界锚，必须另给轮或意图（路线 3 / 5）；热区出晚了玩家会以为点地是走路 —— 要在「可互动」目标上预画淡色环（桌面光标已经在做，只是太小）。
- **优先级：P0。第一刀。**

验收（下次切片，不是本文件）：

1. 院子触控 SCOUT：可见常驻键 ≤ 6（三肖像算三个）。
2. 点 Kar98k 匣出现「开匣」，不需要先按任何技能。
3. 绕到岗哨背后出现「割喉」，正面出现「口哨」不出「割喉」。
4. 近尸体出现「搜尸 / 拖尸」。
5. 肖像不再覆盖中庭（顶边 y > 720−156−108，即贴在底盘上沿）。
6. 冒烟现有 `SMOKE_OK_TOUCH_CROUCH` / `SMOKE_OK_KO` 仍绿；加一条「触控 SETUP 可见键 ≤ N」。

## 4. 路线 3 — 径向菜单 / 长按技能轮

**主张：** 敢死队技能条在触屏上的替代品是「长按肖像出轮」，不是再做一排 54px 键。

### 4.1 绑定现有角色表

`C2Skills.for_role` 已经按兵种给 5 个 id：

| 角色 | 轮面（顺时针） |
|---|---|
| 灰狼 | 匍匐 · 割喉 · 诱饵 · 包扎 · 捆绑 |
| 铁砧 | 匍匐 · **埋雷** · 口哨 · 包扎 · 捆绑 |
| 夜枭 | 匍匐 · **望远镜** · 诱饵 · 割喉 · 捆绑 |

交互：

- **短按肖像** = 选中（现 `picked`）。
- **长按 ≥ 350ms** = 在肖像上方弹出轮；滑向一格松手确认；滑回中心取消。
- 冷却仍用 `skill_cds` 和 `Skills.cooldown`（口哨 4.2s、望远镜 6s、包扎 8s…）。
- 世界物动词（开匣/割喉/拖尸）**优先走热区**。轮是「对着空气也能放」的溢出：望远镜、诱饵落点、埋雷、包扎。

不要做屏幕中央大轮——右下/左下贴边，拇指够得到。轮半径 ~110px，每楔 ≥ 48px 高。

### 4.2 和技能条的关系

| 平台 | 技能条 | 轮 |
|---|---|---|
| 桌面 | 保留（键鼠扫视快） | 不做 |
| 手机 | 关 | 开 |
| 平板 ≥ 900px 高或宽 | 可保留技能条 | 轮可选 |

### 4.3 利弊与优先级

- **利：** 角色个性（铁砧埋雷、夜枭望远镜）不从手机消失；C/Q/W/Z 的「4–8 格热条」不再和底栏抢位。
- **弊：** 长按与「长按目的地奔跑」冲突 —— 奔跑必须发生在**地图**上，轮必须发生在**肖像**上，两套长按分区要写进教程；误触会放口哨，岗哨会转头。第一版可把口哨只放在近岗哨热区，不放进轮。
- **优先级：P1。** 热区先上，轮补空地技能。没有轮的时候，手机可以暂时没有望远镜/埋雷（桌面仍有），夜枭/铁砧在触屏上少一句个性，可接受一个版本。

## 5. 路线 4 — 单兵焦点模式

**主张：** 触屏一次只深度操作一个人。另外两个人是「待命」或「跟上」的跟班，不是三个可同时微操的 RTS 单位。

### 5.1 现在缺什么

- 选中逻辑已是单人（`_select_op`，没有框选）。
- 未选中的人**站住不动**，没有跟随。
- 触控时左卡 + 肖像都能选，等于两套焦点。
- 警报中走位已锁，焦点模式天然成立；痛点只在 SCOUT / SWEEP。

### 5.2 手机规则

1. 只有选中干员接受走、热区、轮。
2. 另外两人状态机只有两个：
   - **待命**（默认，即现状）：保持站位/朝向/匍匐。
   - **跟上**：沿网格走到选中者身后一格，遇岗哨锥停下（用现成 dest X 画鬼路径）。
3. 切换：点肖像 = 换焦点（镜头 `cam_follow` 已能跟）；肖像角标「跟」切换跟上/待命。不要做第三态「各自搜刮」。
4. 左轨三卡在手机上关掉，避免和肖像抢选。
5. 递装、换枪只发生在焦点人物的背包面板。

### 5.3 利弊与优先级

- **利：** 拇指不必在三人之间来回点技能；和「点选单兵」的 Commandos 2 范本一致（范本也是一次一人，不是群控）。
- **弊：** 「跟上」会把人带进黄锥 —— 必须在锥边缘刹车，并允许点肖像把那人拉回待命；三人分头开匣的效率下降，这是故意的（简配夜袭用时间换少误触）。
- **优先级：P1。** 第一刀不需要跟班 AI：先做到「只有焦点人吃指令 + 关掉左卡」。跟上是第二刀。

桌面保持可快速切 1/2/3，不必跟上。键鼠切人成本低，分头行动是桌面的技能天花板。

## 6. 路线 5 — 两阶段输入（先点意图，再点地图）

**主张：** 先选「我在干什么」，再点地，用来消掉模式键（绊索/雷点/射界/诱饵）。

### 6.1 三个意图，不是六个工具

| 意图 | 点地图 = | 点世界物 = |
|---|---|---|
| **潜行**（默认） | 走（若开着匍则静走） | 岗哨 → 割喉/口哨；灌木 → 钻进去 |
| **搜刮** | 走向最近匣/尸 | 匣/尸 → 开/搜/拖 |
| **布置** | 空地 → 雷点；路线格 → 绊索；选中人身上拖 → 射界 | 掩体 → 上掩体 |

意图条放在肖像**上面**一条，三段，高 36px，不要做成第三套底栏。警报 CTA 仍独立。

和情境热区的关系：意图是**过滤器**。潜行时匣仍可出「开匣」，但空地点地不会放雷。布置时点岗哨不出割喉。

### 6.2 利弊与优先级

- **利：** 绊索/雷点/射界这些「先进入工具再点地」的桌面模式，在触屏上最容易误触；意图把它们收成一种。
- **弊：** 经典模式错误（以为在搜刮其实在布置，点地放了一个雷点）。《模拟城市》《模拟人生》都踩过。热区已经能消化大部分世界动词之后，意图条的收益变小。
- **优先级：P2。** 只在 P0 热区做完、玩家仍把雷点/绊索点乱时再加。不要和 P0 同一周上，否则教学要同时讲热区和意图。

桌面不需要意图条，键就是意图。

## 7. 路线 6 — 警报期彻底简化

**主张：** 警报中零微操 —— 这已经是契约。UI 还没跟上。

### 7.1 契约 vs 底栏

`COMMANDOS_RAID.md` / `COMMANDOS2_KIT.md`：ALERT 走位锁，自动开火 + 自动手雷。玩家只该看、暂停、倍速、中止。

现状 WATCH 行 10 个控件（[`02_alert_touch_watch.png`](eval_touch_ux/02_alert_touch_watch.png)）：

**中止 · 自动雷 · 终局 · 暂停 · 1× · 下一波芯片 · 复盘 · 静音 · 日志 · 菜单**

| 控件 | 手机警报 | 去哪 |
|---|---|---|
| 暂停 / 继续 | **留** | 中下 |
| 1× / 2× | **留** | 中下 |
| 下一波 N 路 Xs | **留，只读** | 不是按钮 |
| 中止 | **留，要确认** | 左或进暂停 |
| 自动雷 | 默认开，**藏** | 暂停菜单。契约就是自动丢 |
| 终局 | **桌面/调试** | 跳波不是手机要的 |
| 复盘 | 失败/通关才有意义 | 结果牌上已有 |
| 静音 / 日志 / 菜单 | 进暂停 | `PauseOverlay` 已存在，返回键已打开它 |

警报中肖像：可以留作「看谁在打」，但必须贴底，不能盖掩体（§1.3）。技能条已经在 ALERT 关掉，对。小地图手机关掉。左卡关掉。

### 7.2 利弊与优先级

- **利：** 和玩法承诺一致；WATCH 行从 10 个收到 3 个键 + 1 个只读芯片；「终局」不再被当成正规跳关。
- **弊：** 无。自动雷开关给想关友伤的人留在暂停里即可。
- **优先级：P0，工作量 XS。** 可以和热区同一刀，也可以先单独收。不改模拟。

复杂度全压在 SCOUT —— 这正是 RAID 从「锁死观战」改成「搜刮夜袭」时就选定的。触屏只要把这句话做彻底。

## 8. 路线 7 — 平板 / 横屏 / 安全区 / 拇指

### 8.1 已有的

- `project.godot`：`window/handheld/orientation=0` **锁横屏**；竖着 16:9 留边，不转内容。
- `touch_hud._apply_safe_area()` 已读 `DisplayServer.get_display_safe_area()`，写左右下 margin。
- `_want_touch()`：Android / mobile feature / 触摸屏 / 设置里「触控底栏」。
- 失败/通关牌：触控且宽 < 1100 时单列（`_is_wide_result`）。
- 触控时隐藏桌面 `BottomBar` + `ExtraBar`，避免三层底栏。这一条是对的，留着。

问题不在「没做安全区」，在「安全区里塞了 16 个键，再在底盘上方把肖像顶进地图」。

### 8.2 建议断点

| 表面 | 宽（虚拟） | 布局 |
|---|---|---|
| **手机横屏**（默认） | < 1100 或 `is_handheld()` | §3 常驻底栏；无左卡；无小地图；无技能条；热区；警报 3 键 |
| **平板横屏** | ≥ 1100 | 肖像 + 技能条可同时在；小地图开；仍无左卡（避免三套身份）；热区仍在，底栏不必 16 键 |
| **桌面键鼠** | 任意，触控关 | v0.5 全套：左卡 + 肖像 + 技能条 + 光标 + 键 |
| **竖屏** | — | **不做**。锁横屏已经写进 ANDROID.md，改竖屏等于重做地图 40×22 的构图 |

### 8.3 拇指热区（横屏）

```
左下 280×140     肖像切换（焦点）
中下 其余×88     匍匐粘滞、背包。禁止再堆 16 键
右下 280×140     警报 CTA，最小 128×64
左缘上半         不要再放三张 220 宽卡
右上 200×120     刘海/圆角，禁止可点小地图
```

双指缩放、边缘平移：桌面已有滚轮和 `edge pan`。手机第一刀用 `cam_follow` 跟选中人，比做一套新手势值。第二刀再加双指缩放。

### 8.4 优先级

- 修肖像锚点 + 安全区底盘：**P0（XS）**。
- 平板断点：**P2**，等手机默认稳定。不要先做「自适应 16 键变两行」——两行 32 个目标更糟。

## 9. 路线 8 — 对标：偷哪一刀，不照搬

都是「战术/潜行放到触屏（或手柄）还成功了」的例子。抄结构，不抄类型。

| 作品 | 它怎么把复杂度从手指上拿掉 | 我们可偷 | 不要偷 |
|---|---|---|---|
| **Hitman GO / Lara Croft GO** | 格子本身就是 UI；一格一步，动词写在目标格上 | 点匣/点岗哨/点掩体 = 动词；少常驻键 | 不要把夜袭改成回合棋盘，不要丢掉实时黄锥 |
| **XCOM: Enemy Within iOS** | 一次「手里一个兵」；先选动作再选格子；大卡、镜头跟着走 | 单兵焦点；两段（选动词→选目标）只用于空地技能 | 不要 AP、不要回合制、不要把 ALERT 改成玩家点射击 |
| **Into the Breach 手机** | 格子当按钮，命中盒巨大，几乎无 chrome | 我们格 32px，点格已经能当 UI；热区按格对齐 | 不要同时回合谜题 |
| **Invisible, Inc. iOS** | 暂停友好；物件出情境；一次一个特工 | SCOUT 可暂停（模拟时钟已有 `sim.paused`）；物件出热区 | 不要改成全隐蔽回合 |
| **Desperados 3 / Shadow Tactics（主机）** | 技能轮 + Shadow Mode（暂停排队） | 肖像长按出轮；可选「SCOUT 暂停再下刀和哨」给桌面 | 不要五人 RTS、爬管道、多层楼（契约已切） |
| **Commandos 2 HD Switch** | 非鼠标设备上用轮 + 锁定单角色，而不是 16 个面键 | 证明 C2 动词在手柄/触屏上活得下来，前提是**不 1:1 映射键盘** | 不要把 HD 的快捷栏原样搬来 |
| **Door Kickers** | 计划是游戏，执行是演出 | 我们已经是这个：SCOUT = 计划，ALERT = 演出。手机把演出 UI 收成观战条 | 不要在警报中开放走位 |
| **Mini Metro** | 每个系统只留一种手势 | ALERT 已经是「零手势自动火力」。SCOUT 应对每个世界物只留一种手势 | 不要抽象成线网，那是另一个游戏 |
| **This War of Mine / Rebel Inc. 手机** | 底栏肖像是**唯一**身份条 | 删左卡，肖像即身份 | 不要日历/心情那套 |
| **MGS: Peace Walker（PSP）** | 一个情境键，标签随目标变（开箱/勒喉/上梯子） | 热区 caption 随 Mode 变，和现在桌面光标文案一致 | 不要第三人称射击 |
| **Bad North** | 系统长在世界上（建筑、阵型），不在工具条 | 雷点、绊索、地雷画成世界图钉，点图钉编辑，不从底栏进工具 | 不要自动作战 RTS |

反例（不要往这边靠）：

- **Arma Tactics 手机**：全战术搬上触屏，点选射击、掩护、库存全在，结果是「能玩的累」。我们的 ALERT 已经拒绝了这条路。
- **Hitman Sniper**：一个动词的射击廊。偷了会把夜袭收成「摆好自动炮」。那是 v0.2 锁死观战，已经扔掉。

**对我们最值的一刀：** Door Kickers 的「计划/演出分离」（已有）+ Hitman GO 的「目标即按钮」+ XCOM iOS 的「一次一个兵」+ C2 主机的「技能轮」。组合起来就是手机默认轨。

## 10. 两条产品轨 + 只做一件时做哪件

### 10.1 手机默认 · 简配夜袭（触屏主路径）

玩家心理模型：「我带着**现在这个人**在院子里做事。靠近能做的事会自己长出来。摆好了按右下那颗警报。枪声响了就看。」

SCOUT 常驻：三肖像、匍匐粘滞、背包、警报 CTA。  
SCOUT 情境：开匣、搜尸、拖尸、割喉、口哨、上掩体、捆绑、包扎。  
SCOUT 溢出（P1）：长按肖像 → 望远镜/埋雷/诱饵。  
ALERT：暂停、倍速、中止、波次只读。走位锁、自动开火、自动手雷。  
SWEEP：与 SCOUT 同一套热区（搜尸、换枪、包扎），CTA 变成「下一波警报 / 撤离封锁」。

跟班：默认待命；P1 才加跟上。  
不做：左卡、小地图点选、16 键底栏、警报中终局跳波、竖屏。

教学：院子教程三步改成「点灰狼 → 点这匣 → 绕到岗哨背后点割喉」。C/Q/W/Z 写成「键鼠」。`docs/ANDROID.md` 触控对照表换成热区，不再列 14 个底栏名。

### 10.2 桌面完整 · 敢死队工具（键鼠主路径）

v0.5 全留。左卡 + 肖像 + 技能条 + 情境光标 + 小地图 + 键位表。双击跑、Shift 慢走、滚轮、中键平移、F1 跟随 / F2 复位。三人分头：1/2/3 切人成本低，是这轨的技能天花板。

触控底栏在桌面默认关（现状如此）。设置里「触控底栏」仍可用于 Steam Deck / 触屏笔电 —— 但应走**手机默认布局**，不要走 16 键翻译器。否则 Deck 上会复现 [`01_scout_touch_crowded.png`](eval_touch_ux/01_scout_touch_crowded.png)。

### 10.3 若只做一件事

**做情境热区 + 把肖像/技能锚点钉回底盘 + 警报底栏收到 3 键。**

这是同一刀 HUD，不是三个功能：

1. `_row_setup` 只留背包（或连背包也进肖像）。世界动词改热区。
2. `c2_director` 肖像 `offset_bottom` 贴着触控底盘上沿，不再相对被压缩的 Root 用桌面数字。
3. `_row_watch` 只留暂停 / 倍速 / 中止 + 波次标签。

预计改动面：`touch_hud.gd`、`c2_director.gd`（锚点）、新建一个 `context_prompt.gd`（从 `context_cursor.gd` 的 Mode 拉出来做 Control 热区）、`main.gd` `apply_touch_command` 已能接 haul/knife/crouch。**不要动** `raid_director.gd`、背包规则、岗哨 LOS、自动手雷。

### 10.4 落地顺序（下次才写代码）

| 序 | 切片 | 路 | 体量 | 依赖 |
|---|---|---|---|---|
| 1 | 肖像/技能锚点修回底盘；左卡在 `_want_touch()` 时隐藏 | 7 + 4 | XS | 无 |
| 2 | SETUP 底栏减到 CTA+包+匍；WATCH 减到 3 键 | 1 + 6 | S | 1 |
| 3 | 情境热区（开匣/搜尸/拖尸/割喉/口哨/掩体/捆/包扎） | 2 | M | 2 |
| 4 | 长按肖像技能轮（空地技能） | 3 | M | 3 |
| 5 | 跟上/待命 | 4 | M | 1 |
| 6 | 意图条 潜行/搜刮/布置 | 5 | M | 3，且被玩家抱怨雷点误触才做 |
| 7 | 平板断点（开小地图+技能条） | 7 | S | 3 |
| 8 | 简配自动（默认匍匐、`few_crates`） | 1 | S | 3，可选 |

同一周不要做 3+5+6。热区、意图、跟班都改「点地是什么意思」，叠在一起教不会。

## 11. 明确不做（本方案边界）

- 不改 RAID 相位，不开放警报中走位。
- 不把岗哨看见变成自动拉警报（契约：看见 ≠ 交火，拉警报仍是提交）。
- 不做框选、编队、Shadow Mode 三人同时排队（那是桌面以后的技能上限，不是手机 P0）。
- 不做竖屏、不做「完整 16 键的两行换行」。
- 不把 6 格背包缩成 2 格「简化库存」——搜刮组合是夜袭的内容，减的是**打开它的手势**，不是格数。
- 不在本文件对应的切片里改 `main.gd` 阶段机或武器表。
